# Tubambe

A video platform built for African creators and the brands who want to reach them.
Every post is monetized from day one, payouts are in local currency.

## Stack
- **Frontend:** Next.js (App Router) + Tailwind CSS
- **Backend/DB/Auth/Storage:** Supabase (Postgres + Storage + Realtime)
- **Payouts (not wired yet):** Flutterwave or Paystack
- **Optional, later:** Cloudflare Stream for automatic video compression/transcoding

## Getting started

1. `npm install`
2. Create a Supabase project (https://supabase.com).
3. Run everything in `supabase/schema.sql` in the Supabase SQL Editor. This sets up every
   table, security policy, the 16+ age trigger, the two storage buckets (`videos`, `avatars`),
   the notification triggers, and realtime for the notification bell.

   > **Upgrading from an earlier version of this app?** The safest path is a fresh Supabase
   > project — this schema changed enough (new tables, a new videos RLS policy, new triggers)
   > that patching an existing database by hand is error-prone. If you must keep existing data,
   > diff your current schema against this file table-by-table before running anything.

4. While testing: Supabase → Authentication → turn OFF "Confirm email" (the built-in email
   sender only allows ~2/hour) and make sure "Allow new users to sign up" is ON. Before real
   users arrive, connect a real email provider and turn confirmation back on.
5. `cp .env.local.example .env.local` and fill in your Supabase URL + anon key.
6. `npm run dev` → http://localhost:3000

## What's in the app

**Layout & playback (TikTok-style)**
- Desktop: sidebar (logo, bell, For You / Explore / Upload / Profile), centered 9:16 video,
  circular action buttons, up/down arrows, ↑/↓ keyboard navigation.
- Phone: full-screen video, buttons overlaid, bottom tab bar.
- Only the on-screen video plays; scrolling away pauses and rewinds it. Only the current ±1
  videos are downloaded, to save data.
- Portrait video fills the card; wide/square video fits inside without cropping.
- Sound is on by default and remembered between visits (one global preference, not per-video —
  an earlier version tracked it per-video and the button could get stuck after scrolling to a
  new post; fixed). Browsers block audio until the first click/tap/keypress on the page — a
  browser rule, not something any app can bypass — so the mute icon alone (no extra "tap for
  sound" hint) reflects whether sound is actually playing right now.
- Views are counted (once per viewing) and shown on every video and every profile grid thumbnail.
- A splash screen shows the Tubambe mark briefly on app open, like TikTok/Instagram
  (`components/SplashScreen.js`).

**Social**
- Like, Comment (with likes and threaded replies + an emoji picker), Repost, Save (bookmark),
  Share (copies a link to `/video/[id]`).
- Pin one video to the top of your own profile (⋯ menu on your own videos).
- Public profiles at `/u/[handle]`: avatar, bio (links are auto-detected and clickable),
  Follow/Unfollow, follower/following counts.
- Profile has Posts / Saved / Reposted tabs (Saved and Reposted are only visible on your own
  profile).
- Clicking a video from a profile grid, Explore, or search results scrolls through that same
  list of videos (not an isolated single video), with a back arrow to return.

**Notifications**
- Likes, comments, replies, comment-likes, reposts, follows, follow accepts, and new uploads
  from people you follow — all generated by database triggers (see `supabase/schema.sql`), so
  they fire even if a client bug would otherwise miss them.
- Bell icon with a live unread badge (Supabase Realtime) in the sidebar/top bar → `/notifications`.

**Privacy**
- Toggle "Private account" in Edit Profile. Real enforcement: a private account's videos are
  only returned by the database to the creator and their **accepted** followers — this is a
  Postgres row-level-security policy, not a UI-only hide, so it can't be bypassed by calling
  the API directly.
- Following a private account creates a pending request; the owner accepts or declines from
  the Notifications page.

**Identity**
- Profile picture (optional) and bio, both editable at `/profile/edit`.

**Upload**
- Just a video and a caption now — category, language, and the monetization line were removed.
  A cover image and duration are captured automatically. 50 MB file-size limit (Supabase
  free-plan default) with a clear error if exceeded.

**Branding**
- Renamed Sauti → Tubambe everywhere. New logo (squircle mark + wordmark) — see
  `components/Logo.js` for the in-app version, `app/icon.svg` for the auto-generated favicon,
  and the separately delivered `tubambe-logo.svg` for a standalone asset.

## Moderation & trust (added for launch readiness)
- **Report** a video, comment, or profile — a reason + optional details go into a `reports`
  table. There's no admin dashboard yet; review reports via Supabase's own Table Editor
  (Table Editor → reports) for now. A real moderation queue UI is worth building once report
  volume justifies it.
- **Block a user** — enforced at the database level (Postgres RLS), not just hidden in the UI:
  once blocked, neither person's videos are returned to the other by the database itself, in
  either direction. Manage blocked accounts at `/blocked`.
- **Delete your own video or comment** — was missing before, now a real policy + UI action.
- **Terms of Service, Privacy Policy, Community Guidelines** (`/terms`, `/privacy`,
  `/guidelines`) — template content, linked from sign-up as a required checkbox. These are
  **not legal advice** — have an actual lawyer review them before relying on them, especially
  given the 16+ age requirement and user-generated content.

## Mobile — PWA now, native later
The app is installable as a Progressive Web App: "Add to Home Screen" gives it a real icon,
splash screen, and full-screen standalone window (no browser address bar) on both iOS and
Android — see `app/manifest.json` and `app/apple-icon.png`. This is not the same as an App
Store / Play Store listing. A native build (e.g. via Capacitor wrapping this same code, or a
separate React Native app) is a real future step, but not a launch blocker — PWA install covers
"feels like an app" for a launch and beyond.

## Remaining honest gaps before a public launch
- **No admin moderation dashboard.** Reports are reviewable in Supabase directly; a proper
  in-app queue (assign, resolve, ban) is the natural next step once this is real.
- **Payouts.** Ad revenue math exists as a screen, but no money actually moves — Flutterwave/
  Paystack integration is still phase 2.
- **Phone-number (OTP) sign-in.** Still email/password only; phone matters more for your
  target users.
- **Feed ranking.** Still newest-first, not a real recommendation algorithm.
- **Video compression.** Files play back exactly as uploaded; fine for testing, worth
  revisiting (e.g. Cloudflare Stream) once real viewers are on constrained data.
- **Blocking doesn't yet stop a blocked person from liking/commenting** — it hides their
  videos from each other, which covers the main harm, but interaction-level blocking (e.g.
  preventing a comment from a blocked account) isn't enforced yet.
- **Nothing here has been tested in a real browser with real data yet** — every round has been
  verified with a production build (catches broken imports/syntax) but not manually clicked
  through by a human. That first real test matters before trusting any of this fully.
